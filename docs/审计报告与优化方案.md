## 一、执行摘要

本次审计对慧宿智联IoT智慧酒店系统进行了全面的软硬件功能审计，涵盖后端服务（34个API模块/160+端点）、Web前端（38个页面）、Flutter APP（40+页面）、硬件模拟器（3种终端）、硬件终端（18个驱动/5个HAL模块）、MQTT通信体系、数据库（40张表）。

### 核心发现

- **系统规模庞大**: 5大子系统、160+API端点、40+数据库表、50+项未写入需求分析的配套功能
- **架构风险**: 发现5个严重问题（MQTT主题格式不一致、SQL文件碎片化、AI知识库双表冲突等）
- **安全缺口**: 消息签名未统一启用、API限流缺失、敏感数据未加密
- **运维债务**: 缺少监控体系、备份策略不完善、部署配置分散

### 建议优先级

1. **立即解决**: SQL文件统一、MQTT主题桥接、数据库字段补充
2. **近期解决**: 消息签名强制启用、API限流、数据库索引优化
3. **长期改进**: 监控体系、自动化运维、代码架构重构

## 三、审计发现的问题清单

### 3.1 🔴 严重问题（需立即解决）

#### P1-1: MQTT主题格式不一致

**风险等级**: 高  
**影响范围**: 硬件/APP通信  
**具体表现**:
- 硬件/模拟器: `hotel/device/command/{type}/{id}`
- APP: `hotel/{hotelId}/room/{roomId}/device/{deviceId}/control`

**影响**: 后端需维护两套主题解析逻辑，增加复杂度和故障点

**建议**: 统一采用硬件端格式，APP通过后端API转发

---

#### P1-2: SQL文件版本碎片化

**风险等级**: 高  
**影响范围**: 数据库部署  
**具体表现**:

| 文件 | 版本 | 表数量 | 关键差异 |
|------|------|--------|----------|
| `init.sql` | v3.4.0 | 25 | 最新，但缺少delivery_orders/control_commands/roles等 |
| `schema.sql` | v2.0.0 | 22 | 含security_events/device_auth，但缺少AI表 |
| `full_init.sql` | v2.2.0 | 21 | 含roles/user_roles，但缺少AI表和review相关 |

**影响**: 没有任何一个SQL文件包含完整的40张表定义

**建议**: 合并为单文件，包含全部表结构

---

#### P1-3: AI知识库双表冲突

**风险等级**: 高  
**影响范围**: AI功能  
**具体表现**:

| 表名 | 来源 | 结构特点 |
|------|------|----------|
| `ai_knowledge_entries` | init.sql | question/answer/keywords/priority/usage_count/fulltext索引 |
| `ai_knowledge_base` | create_ai_knowledge_base.sql | title/content/keywords/sort_order，UNIQUE(hotel_id, category) |

**影响**: 两表功能重叠但结构不同，代码可能随机使用

**建议**: 统一为单表，合并两表优点

---

#### P1-4: 语音通话双通道不兼容

**风险等级**: 高  
**影响范围**: 通话功能  
**具体表现**:
- 硬件端: MQTT音频流，G.711 8kHz编码
- APP端: WebRTC + Socket.IO信令

**影响**: 硬件与APP之间无法直接通话，需后端协议转换

**建议**: 实现语音通话网关，桥接两种协议

---

#### P1-5: MQTT Broker地址不一致

**风险等级**: 高  
**影响范围**: 部署配置  
**具体表现**:
- 硬件默认: `172.20.10.3:1883` (局域网)
- 模拟器/APP: `8.134.166.69:1883` (云服务器)

**影响**: 部署时需手动修改配置，容易出错

**建议**: 统一使用云服务器地址，硬件通过内网DNS解析

---

### 4.2 MQTT通信统一方案

#### 4.2.1 统一主题格式

**采用硬件端格式为标准**:

```
# 设备状态上报
topic: hotel/device/status/{device_type}/{device_id}
示例: hotel/device/status/room/room_101

# 传感器数据上报
topic: hotel/device/data/{device_type}/{device_id}
示例: hotel/device/data/room/room_101

# 设备命令下发
topic: hotel/device/command/{device_type}/{device_id}
示例: hotel/device/command/room/room_101

# 命令执行结果
topic: hotel/device/command/result

# 安全事件
topic: hotel/security/event

# AI语音请求
topic: hotel/ai/request/room/{device_id}

# AI语音响应
topic: hotel/ai/response/room/{device_id}

# 场景控制
topic: hotel/room/{room_id}/scene

# 通话信令
topic: hotel/call/signaling/{call_id}

# 通话音频上行(设备→云端)
topic: hotel/call/audio/{call_id}/up

# 通话音频下行(云端→设备)
topic: hotel/call/audio/{call_id}/down

# 客房服务-送物
topic: hotel/service/delivery/{room_id}/request

# 客房服务-维修
topic: hotel/service/maintenance/{room_id}/request
```

#### 4.2.2 APP端适配方案

APP不再直接订阅MQTT，改为通过**后端API + WebSocket**:

```typescript
// 后端新增WebSocket事件
```

```typescript
class MQTTService {
  // 过渡期桥接：将APP格式转换为硬件格式
  private bridgeTopic(appTopic: string): string | null {
    // APP格式: hotel/{hotelId}/room/{roomId}/device/{deviceId}/control
    // 转换为: hotel/device/command/room/{deviceId}
    const match = appTopic.match(/hotel\/(\d+)\/room\/(\d+)\/device\/(.+)\/control/);
    if (match) {
      const [, hotelId, roomId, deviceId] = match;
      return `hotel/device/command/room/${deviceId}`;
    }
    return null;
  }

  // 处理APP发来的消息
  async handleAppMessage(appTopic: string, payload: any): Promise<void> {
    const hardwareTopic = this.bridgeTopic(appTopic);
    if (hardwareTopic) {
      await this.publish(hardwareTopic, payload);
    }
  }
}
```

```typescript
        message: err.message,
        details: err.details
```

```typescript
// infrastructure/encryption/index.ts
import crypto from 'crypto';

export class EncryptionService {
  private algorithm = 'aes-256-gcm';
  private key: Buffer;

  constructor() {
    const keyHex = process.env.ENCRYPTION_KEY;
    if (!keyHex || keyHex.length !== 64) {
      throw new Error('ENCRYPTION_KEY must be 32 bytes (64 hex characters)');
    }
    this.key = Buffer.from(keyHex, 'hex');
  }

  encrypt(text: string): string {
    const iv = crypto.randomBytes(16);
    const cipher = crypto.createCipheriv(this.algorithm, this.key, iv);
    const encrypted = Buffer.concat([cipher.update(text, 'utf8'), cipher.final()]);
    const authTag = cipher.getAuthTag();
    return `${iv.toString('hex')}:${authTag.toString('hex')}:${encrypted.toString('hex')}`;
  }

  decrypt(encryptedData: string): string {
    const [ivHex, authTagHex, encryptedHex] = encryptedData.split(':');
    const decipher = crypto.createDecipheriv(
      this.algorithm,
      this.key,
      Buffer.from(ivHex, 'hex')
    );
    decipher.setAuthTag(Buffer.from(authTagHex, 'hex'));
    return decipher.update(encryptedHex, 'hex') + decipher.final('utf8');
  }
}

// 使用示例
const encryption = new EncryptionService();

// 加密身份证号

// 解密
const idNumber = encryption.decrypt(encryptedIdNumber);
```
