> **负责人**：陈剑涛

## 二、 接口设计与文档 (API Design)

### 2.1 设计标准
*   **风格规范**：采用 RESTful API 架构，资源路径清晰（如 `/api/v1/bookings`）。
*   **认证机制**：基于 JWT (JSON Web Token) 的无状态认证，确保接口调用安全。
*   **响应格式**：统一的 JSON 返回结构，包含 `success`, `data`, `message`。

### 2.2 核心接口演示集 (Demo Endpoints)
| 功能模块 | 接口路径 | 方法 | 说明 |
| :--- | :--- | :--- | :--- |
| **身份认证** | `/api/v1/auth/login` | POST | 演示不同角色（管理员/前台/住客）的安全登录。 |
| **房态调度** | `/api/v1/rooms/status` | PATCH | 演示前台手动切换房态与实时推送。 |
| **订单协同** | `/api/v1/bookings` | POST | 演示住客下单、支付到订单自动确认的全流程。 |
| **IoT 联动** | `/api/v1/iot/control` | POST | 演示通过 Web/APP 下发 MQTT 指令控制硬件设备。 |

## 四、 数据库架构与优化 (Database Architecture)

### 4.1 技术选型
*   **引擎**：MySQL 8.0 (InnoDB)，支持 ACID 事务特性，保障财务与房态数据的强一致性。
*   **连接池配置**：
    - `connectionLimit`: 10 (平衡资源占用与响应速度)。
    - `enableKeepAlive`: 开启 (解决远程连接不稳定的 ECONNRESET 问题)。
    - `connectTimeout`: 10,000ms。

### 4.2 核心优化手段
*   **索引优化**：针对 `booking_number`, `device_id`, `phone` 建立了唯一索引；对 `room_status` 等高频筛选字段建立了复合索引。
*   **事务保障**：在办理入住（Check-in）与退房（Check-out）过程中，使用 SQL 事务确保订单状态与房间实体状态同步更新。
*   **缓存策略**：集成 Redis 存储设备影子（Device Shadow），减少对物理数据库的直接读取压力。
