# 后端与数据库版本更新对齐说明

## 1. 背景与目标

当前本地开发版本与服务器运行版本在后端接口实现、数据库表结构上存在差异。  
本说明用于指导一次可回滚的更新流程，确保：

- 后端代码与数据库结构同步
- 新旧接口兼容关系明确
- 更新后可快速验证业务链路
- 失败时可按预案回退

## 2. 适用范围

- 后端目录：`backend/iot-hotel-backend`
- 数据库：`hotel_system`（MySQL）
- 重点模块：预订、入住退房、房态、工单、送物、语音通话、会员

## 4. 差异盘点模板（更新前填写）

### 4.1 后端接口差异

| 模块 | 本地接口行为 | 服务器接口行为 | 结论 |
|---|---|---|---|
| 预订创建 | 创建时写入 `hotel_id` | 可能未写入 `hotel_id` | 必须对齐 |
| 房间列表 | 前台请求频次高，需去重缓存 | 服务器可能触发 429 限流 | 建议对齐 |
| 入住办理 | 支持今日预订回填/同住人扩展字段 | 服务器可能缺少扩展处理 | 需确认兼容 |

### 4.2 数据库结构差异

| 表 | 字段/索引差异 | 风险 |
|---|---|---|
| `bookings` | `hotel_id` 是否 NOT NULL 且无默认值 | 创建失败（500） |
| `rooms` | `hotel_id` 是否存在且有效 | 关联查询异常 |
| 其他业务表 | 新增字段是否已上线 | 接口读写不一致 |

## 5. 正式更新流程

## 5.1 进入维护窗口

- 暂停前台关键写操作（预订、入住、退房）
- 通知业务侧更新时间段

## 5.2 备份

### 代码备份

```bash
cd /root/IoT_Smart_Hotel_System
git tag backup-before-update-$(date +%Y%m%d-%H%M%S)
```

### 数据库备份

```bash
mysqldump -u iot_user -p hotel_system > /root/backup_hotel_system_$(date +%Y%m%d-%H%M%S).sql
```

## 5.3 部署后端代码

```bash
cd /root/IoT_Smart_Hotel_System
git pull

cd backend/iot-hotel-backend
npm ci
npm run build
pm2 restart iot-hotel-backend
pm2 status iot-hotel-backend
```

## 5.4 执行数据库结构对齐

优先使用项目已有 migration 脚本：

- `database/migrations/add_auth_tables.sql`
- `database/migrations/add_room_types.sql`
- `database/migrations/add_room_types_v2.sql`
- `database/migrations/update_devices_table.sql`

执行前先审阅 SQL，确认与线上当前结构不冲突。

## 5.5 数据一致性校验（关键）

```sql
SELECT COUNT(*) AS rooms_without_hotel FROM rooms WHERE hotel_id IS NULL;
SELECT COUNT(*) AS bookings_without_hotel FROM bookings WHERE hotel_id IS NULL;
SELECT COUNT(*) AS bad_booking_room_ref
FROM bookings b LEFT JOIN rooms r ON b.room_id = r.id
WHERE r.id IS NULL;
```

若结果非 0，需先清理再开放业务写入。

## 6. 更新后验收清单

## 6.1 接口健康检查

```bash
curl http://127.0.0.1:9000/api/v1/health
curl http://127.0.0.1:9000/api/v1/rooms
curl http://127.0.0.1:9000/api/v1/bookings?pageSize=5
```

## 6.2 业务回归（前台端）

- 新建预订成功，无 `hotel_id` 相关 500
- 入住办理页面可打开，无 mounted 未捕获异常
- 切换前台页面不出现连续 429
- 工单/送物角标正常显示

## 6.3 日志观察

```bash
pm2 logs iot-hotel-backend --lines 200 --nostream
```

重点确认：

- 无 `ER_NO_DEFAULT_FOR_FIELD`
- 无连续 `429` 峰值
- 无新增 500 高频错误

## 7. 回滚预案

若更新后出现核心链路异常，按以下顺序回滚：

1. 停止新写流量
2. 代码回滚到备份 tag
3. 重启后端服务
4. 必要时恢复数据库备份

```bash
cd /root/IoT_Smart_Hotel_System
git checkout <backup-tag>
cd backend/iot-hotel-backend
npm ci
npm run build
pm2 restart iot-hotel-backend
```

数据库回滚：

```bash
mysql -u iot_user -p hotel_system < /root/backup_hotel_system_xxx.sql
```
