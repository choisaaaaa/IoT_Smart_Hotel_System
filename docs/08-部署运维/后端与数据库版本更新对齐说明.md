# 后端与数据库版本更新对齐说明（简版覆盖更新）

## 1. 适用场景

适用于“直接覆盖更新”：

- 服务器代码落后，直接用当前仓库版本覆盖
- 数据库结构有差异，按项目 SQL 脚本补齐
- 不做复杂灰度，不做分批发布

## 2. 一次性覆盖更新步骤

### 2.1 拉取最新代码

```bash
cd /root/IoT_Smart_Hotel_System
git pull
```

### 2.2 更新后端并重启

```bash
cd /root/IoT_Smart_Hotel_System/backend/iot-hotel-backend
npm ci
npm run build
pm2 restart iot-hotel-backend
pm2 status iot-hotel-backend
```

### 2.3 执行数据库结构更新

按顺序执行项目内 SQL（已存在则跳过）：

```bash
mysql -u iot_user -p hotel_system < /root/IoT_Smart_Hotel_System/backend/iot-hotel-backend/database/migrations/add_auth_tables.sql
mysql -u iot_user -p hotel_system < /root/IoT_Smart_Hotel_System/backend/iot-hotel-backend/database/migrations/add_room_types.sql
mysql -u iot_user -p hotel_system < /root/IoT_Smart_Hotel_System/backend/iot-hotel-backend/database/migrations/add_room_types_v2.sql
mysql -u iot_user -p hotel_system < /root/IoT_Smart_Hotel_System/backend/iot-hotel-backend/database/migrations/update_devices_table.sql
```

如你有自己的增量 SQL，继续追加执行即可。

## 3. 更新后最小验证

### 3.1 服务状态

```bash
pm2 status iot-hotel-backend
curl http://127.0.0.1:9000/api/v1/health
```

### 3.2 核心接口

```bash
curl http://127.0.0.1:9000/api/v1/rooms
curl "http://127.0.0.1:9000/api/v1/bookings?pageSize=5"
```

### 3.3 关键业务点

- 前台“新建预订”可成功
- 不再出现 `Field 'hotel_id' doesn't have a default value`
- 入住页可打开，不出现 mounted 未捕获异常

## 4. 出问题时快速回滚

```bash
cd /root/IoT_Smart_Hotel_System
git reset --hard HEAD~1
cd backend/iot-hotel-backend
npm ci
npm run build
pm2 restart iot-hotel-backend
```

如果数据库也改坏，再恢复你自己的备份 SQL。
