# IoT 智慧酒店系统 - 4.12 重构规范开发内容

> 版本: v1.0 | 更新日期: 2026-04-12 | 维护人: Yzj

## 1. 重构背景

2026年4月12日，系统在多端联调测试中发现支付状态不同步、在线入住404、前台今日预订不显示等严重问题，经排查发现根因涉及后端支付逻辑、路由注册、前端过滤逻辑、移动端import路径等多个层面。本次重构旨在修复所有已知问题，并建立规范防止同类问题再次发生。

***

## 2. 已修复问题清单

### 2.1 支付状态不同步（严重）

**问题描述**：顾客完成支付后，顾客端显示"未支付"，前台端显示"待确认"，数据库中订单状态仍为 `pending`。

**根因分析**：

1. `payment.controller.ts` 创建支付时从 `req.user.hotel_id` 获取 hotel\_id，而顾客的 hotel\_id=0
2. `payment.service.ts` 确认支付时使用 `hotel_id` 作为 WHERE 条件更新订单状态，导致匹配0行

**修复方案**：

| 文件                      | 修改内容                                                                    |
| ----------------------- | ----------------------------------------------------------------------- |
| `payment.controller.ts` | 创建支付时从关联订单（bookings/delivery\_orders/maintenance\_tickets）中获取 hotel\_id |
| `payment.service.ts`    | 确认支付时移除 hotel\_id 条件，仅使用 `id` 主键更新订单状态                                  |

**修复前代码**：

```typescript
// payment.controller.ts - 错误：从用户获取hotel_id
let hotel_id = req.user?.hotel_id || 1;

// payment.service.ts - 错误：hotel_id条件导致匹配0行
await connection.query(
  'UPDATE bookings SET status = ? WHERE id = ? AND hotel_id = ?',
  ['confirmed', payment.order_id, payment.hotel_id]
);
```

**修复后代码**：

```typescript
// payment.controller.ts - 正确：从订单获取hotel_id
if (order_type === 'booking' && order_id) {
  const [rows] = await pool.query('SELECT hotel_id FROM bookings WHERE id = ?', [Number(order_id)]);
  if (Array.isArray(rows) && rows.length > 0) {
    hotel_id = (rows[0] as any).hotel_id || 1;
  }
}

// payment.service.ts - 正确：仅用主键更新
await connection.query(
  'UPDATE bookings SET status = ? WHERE id = ?',
  ['confirmed', payment.order_id]
);
```

### 2.2 在线办理入住404错误（严重）

**问题描述**：手机端支付后点击"确认办理"按钮报404错误。

**根因分析**：`bookings.ts` 路由注册顺序错误，`/checkin-online/:id` 在 `/:id` 之后注册，导致 `checkin-online` 被当作 id 参数匹配到 `getById`。

**修复方案**：调整路由注册顺序，特殊路径在参数路径之前。

```typescript
// 正确顺序 ✅
router.post('/checkin-online/:id', bookingController.checkinOnline);
router.post('/:id/checkin-online', bookingController.checkinOnline);
router.get('/:id', bookingController.getById);

// 错误顺序 ❌
router.get('/:id', bookingController.getById);
router.post('/checkin-online/:id', bookingController.checkinOnline);
```

### 2.3 接待中心今日预定清单不显示已确认订单（严重）

**问题描述**：前台端接待中心的今日预定清单只显示 `pending` 状态的订单，已确认（`confirmed`）的订单不显示。

**根因分析**：Web端 `CheckInOut.vue` 过滤逻辑只包含 `pending` 和 `pre_checked_in`，遗漏了 `confirmed` 状态。

**修复方案**：

```javascript
// 修复前 ❌
const list = allList.filter((item) =>
  ['pending', 'pre_checked_in'].includes(item.status)
)

// 修复后 ✅
const list = allList.filter((item) =>
  ['pending', 'confirmed', 'pre_checked_in'].includes(item.status)
)
```

### 2.4 App端前台Dashboard不按日期过滤（中等）

**问题描述**：App端前台Dashboard显示所有日期的预订，而非仅显示今日预订。

**修复方案**：

1. `booking_service.dart` 添加 `check_in_date` 查询参数
2. `dashboard_page.dart` 使用 `checkInDate: 'today'` 过滤今日预订
3. 添加状态过滤：只显示 `pending/confirmed/pre_checked_in/checked_in`

### 2.5 在线入住未支付校验漏洞（严重）

**问题描述**：未支付的预订也可以办理在线入住，存在业务逻辑漏洞。

**根因分析**：`checkinOnline` 方法允许 `pending` 状态办理入住，且未检查支付记录。

**修复方案**：

1. 将允许入住的状态从 `['pending', 'confirmed', 'pre_checked_in']` 改为 `['confirmed', 'pre_checked_in']`
2. 新增支付记录校验：必须存在 `status='paid'` 的支付记录

```typescript
if (!['confirmed', 'pre_checked_in'].includes(booking.status)) {
  return res.status(400).json(errorResponse('当前预订状态不允许办理入住，请先完成支付'));
}

const [paymentRows] = await connection.query(
  'SELECT id FROM payments WHERE order_type = ? AND order_id = ? AND status = ? LIMIT 1',
  ['booking', id, 'paid']
);
if (paymentRows.length === 0) {
  return res.status(400).json(errorResponse('请先完成支付后再办理入住'));
}
```

### 2.6 room\_service\_page.dart import路径错误（中等）

**问题描述**：`room_service_page.dart` 的 import 路径使用了 `../../../` 但文件在 `lib/pages/guest/` 目录下，应使用 `../../`。

**修复方案**：将所有 `../../../` 修正为 `../../`。

### 2.7 CouponManage.vue useUserStore未定义（中等）

**问题描述**：Web端 `CouponManage.vue` 使用了 `useUserStore()` 但未导入，项目使用的是 `useAppStore`。

**修复方案**：

```javascript
// 修复前 ❌
const userStore = useUserStore()

// 修复后 ✅
import { useAppStore } from '@/stores/app'
const userStore = useAppStore()
```

## 4. 规范化约束（新增）

### 4.1 后端开发约束

| 编号    | 约束           | 说明                                                                    |
| ----- | ------------ | --------------------------------------------------------------------- |
| R-001 | hotel\_id 来源 | 创建支付/操作时，hotel\_id 必须从关联业务订单获取，禁止从 users.hotel\_id 获取                 |
| R-002 | 状态更新条件       | 更新订单状态时，WHERE 条件使用主键 id，禁止使用 hotel\_id                                |
| R-003 | 路由注册顺序       | 特殊路径（/lookup, /calculate-price, /checkin-online/:id）必须在参数路径（/:id）之前注册 |
| R-004 | 在线入住校验       | 必须校验预订状态为 confirmed/pre\_checked\_in 且存在已支付记录                         |
| R-005 | 事务使用         | 涉及多表更新的操作（支付确认、入住办理）必须使用数据库事务                                         |
| R-006 | 乐观锁          | bookings 表更新时检查 lock\_version 防止并发冲突                                  |

### 4.2 前端开发约束

| 编号    | 约束       | 说明                                                               |
| ----- | -------- | ---------------------------------------------------------------- |
| F-001 | 状态过滤完整性  | 今日预订清单必须包含 pending/confirmed/pre\_checked\_in/checked\_in 所有活跃状态 |
| F-002 | Store 引用 | 使用 useAppStore 而非 useUserStore，统一从 @/stores/app 导入               |
| F-003 | 日期过滤     | 前台端预订列表必须按 check\_in\_date 过滤今日数据                                |

### 4.3 移动端开发约束

| 编号    | 约束        | 说明                                                          |
| ----- | --------- | ----------------------------------------------------------- |
| M-001 | import 路径 | lib/pages/guest/ 下的文件引用 lib/core/ 和 lib/services/ 使用 ../../ |
| M-002 | 日期过滤      | 前台 Dashboard 使用 checkInDate: 'today' 过滤今日预订                 |
| M-003 | 状态过滤      | 前台预订列表过滤 pending/confirmed/pre\_checked\_in/checked\_in     |
