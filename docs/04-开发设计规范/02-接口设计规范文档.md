## 2. 通用规范

### 2.1 请求规范

#### 请求头

```
Content-Type: application/json
Authorization: Bearer {token}
```

#### 请求方法

| 方法     | 用途        | 幂等性 |
| ------ | --------- | --- |
| GET    | 查询资源      | 是   |
| POST   | 创建资源/执行操作 | 否   |
| PUT    | 全量更新      | 是   |
| PATCH  | 部分更新      | 是   |
| DELETE | 删除资源      | 是   |

#### 查询参数规范

| 参数              | 类型     | 说明                |
| --------------- | ------ | ----------------- |
| page            | number | 页码，默认1            |
| pageSize        | number | 每页数量，默认10         |
| status          | string | 状态过滤              |
| hotel\_id       | number | 酒店ID过滤            |
| check\_in\_date | string | 入住日期过滤，支持 `today` |
| guest\_name     | string | 客人姓名模糊搜索          |

### 2.2 响应规范

#### 统一响应格式

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {},
  "timestamp": 1775943483000
}
```

#### 分页响应格式

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "list": [],
    "total": 100,
    "page": 1,
    "pageSize": 10
  }
}
```

#### HTTP状态码规范

| 状态码 | 含义    | 使用场景                    |
| --- | ----- | ----------------------- |
| 200 | 成功    | GET/PUT/PATCH/DELETE 成功 |
| 201 | 创建成功  | POST 创建资源成功             |
| 400 | 请求错误  | 参数校验失败、业务逻辑错误           |
| 401 | 未认证   | Token无效或过期              |
| 403 | 无权限   | 角色权限不足                  |
| 404 | 不存在   | 资源未找到                   |
| 500 | 服务器错误 | 内部异常                    |

#### 业务错误码规范

| code | 含义      |
| ---- | ------- |
| 200  | 成功      |
| 400  | 请求参数错误  |
| 401  | 未认证     |
| 403  | 无权限     |
| 404  | 资源不存在   |
| 500  | 服务器内部错误 |

## 3. 核心接口详细设计

### 3.1 认证接口 `/auth`

| 方法   | 路径               | 说明       | 认证 |
| ---- | ---------------- | -------- | -- |
| POST | `/auth/login`    | 手机号+密码登录 | 否  |
| POST | `/auth/register` | 用户注册     | 否  |
| POST | `/auth/refresh`  | 刷新Token  | 是  |
| POST | `/auth/logout`   | 退出登录     | 是  |

### 3.2 预订接口 `/bookings`

| 方法    | 路径                                 | 说明        | 认证 | 权限          |
| ----- | ---------------------------------- | --------- | -- | ----------- |
| GET   | `/bookings`                        | 预订列表      | 是  | 全角色         |
| POST  | `/bookings`                        | 创建预订      | 是  | 全角色         |
| GET   | `/bookings/:id`                    | 预订详情      | 是  | 全角色         |
| PUT   | `/bookings/:id/confirm`            | 确认预订      | 是  | admin/staff |
| PUT   | `/bookings/:id/checkin`            | 前台办理入住    | 是  | admin/staff |
| POST  | `/bookings/:id/checkin-online`     | 在线办理入住    | 否  | customer    |
| PUT   | `/bookings/:id/reject-pre-checkin` | 拒绝预入住     | 是  | admin/staff |
| PUT   | `/bookings/:id/checkout`           | 退房        | 是  | 全角色         |
| PUT   | `/bookings/:id/cancel`             | 取消预订      | 是  | 全角色         |
| PUT   | `/bookings/:id/extend`             | 续住        | 是  | 全角色         |
| PATCH | `/bookings/:id/status`             | 更新状态      | 是  | admin/staff |
| GET   | `/bookings/lookup`                 | 预订查询(免登录) | 否  | 公开          |
| GET   | `/bookings/calculate-price`        | 计算价格      | 是  | 全角色         |

**在线入住接口重要约束：**

- 预订状态必须为 `confirmed` 或 `pre_checked_in`
- 必须存在已支付（`paid`）的支付记录
- 请求体必须包含 `guest_phone`, `real_name`, `id_number`

## 4. 接口开发规范

### 4.1 路由注册规范

1. **路由顺序**：特殊路径必须在参数路径之前注册
   ```typescript
   // 正确 ✅
   router.get('/lookup', controller.lookup);
   router.get('/calculate-price', controller.calcPrice);
   router.post('/checkin-online/:id', controller.checkinOnline);
   router.get('/:id', controller.getById);

   // 错误 ❌ - /:id 会匹配 lookup
   router.get('/:id', controller.getById);
   router.get('/lookup', controller.lookup);
   ```
2. **认证中间件**：需要认证的路由必须添加 `authenticate`
3. **授权中间件**：需要角色控制的路由必须添加 `authorize([角色列表])`

### 4.2 控制器开发规范

1. 所有控制器方法必须使用 `try-catch` 包裹
2. 使用 `AuthRequest` 类型获取当前用户信息
3. 错误响应使用 `errorResponse()` 工具函数
4. 成功响应使用 `successResponse()` 工具函数
5. 数据库操作必须使用参数化查询，禁止字符串拼接SQL

### 4.3 跨组件数据一致性规范

1. **支付→订单状态联动**：支付确认后必须同步更新关联订单状态
2. **订单→房间状态联动**：预订确认后房间变为 `reserved`，入住后变为 `occupied`
3. **hotel\_id 一致性**：跨表操作时 hotel\_id 必须从业务数据获取，不从用户信息获取
4. **事务使用**：涉及多表更新的操作必须使用数据库事务
