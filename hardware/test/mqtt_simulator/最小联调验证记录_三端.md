# 硬件三端最小联调验证记录（无实体硬件）

> 目标：在不接外设的前提下，验证三端 MQTT 上线消息/心跳消息、Topic 命名、JSON 字段与通讯规范的一致性。

---

## 1. 验证范围

- `room_terminal`：上线状态、温湿度上报、安防事件、指令执行回执
- `front_desk_terminal`：上线状态、心跳上报
- `floor_controller`：上线状态、光照上报、群控指令回执

---

## 2. 验证脚本

- `hardware/test/mqtt_simulator/test_room_301.js`
- `hardware/test/mqtt_simulator/test_front_desk_01.js`
- `hardware/test/mqtt_simulator/test_floor_03.js`

运行方式（分别执行）：

```powershell
cd hardware/test/mqtt_simulator
npm install
node test_room_301.js
node test_front_desk_01.js
node test_floor_03.js
```

---

## 3. Topic 与字段一致性核对

### 3.1 客房端 (`room_301`)

- **上线 Topic**：`hotel/device/status/room/room_301`
  - 字段：`device_id`、`device_type`、`status`、`firmware_version`、`timestamp`
- **心跳/遥测 Topic**：
  - `hotel/device/data/temperature/room_301`
  - `hotel/device/data/humidity/room_301`
  - 字段：`device_id`、`sensor_type`、`value`、`unit`、`timestamp`
- **安防事件 Topic**：`hotel/security/event`
  - 字段：`device_id`、`event_type`、`event_data`、`level`、`timestamp`
- **回执 Topic**：`hotel/device/command/result`
  - 字段：`device_id`、`command_id`、`command_type`、`status`、`result`、`timestamp`

### 3.2 前台端 (`front_desk_01`)

- **上线/心跳 Topic**：`hotel/device/status/front_desk/front_desk_01`
  - 上线字段：`device_id`、`device_type`、`status`、`firmware_version`、`timestamp`
  - 心跳字段：`device_id`、`status`、`battery_level`、`signal_strength`、`uptime`、`memory_usage`、`cpu_usage`、`timestamp`

### 3.3 楼控端 (`floor_03`)

- **上线 Topic**：`hotel/device/status/floor/floor_03`
  - 字段：`device_id`、`device_type`、`status`、`firmware_version`、`timestamp`
- **遥测 Topic**：`hotel/device/data/light/floor_03`
  - 字段：`device_id`、`sensor_type`、`value`、`unit`、`timestamp`
- **回执 Topic**：`hotel/device/command/result`
  - 字段：`device_id`、`command_id`、`command_type`、`status`、`result`、`timestamp`

---

## 4. 结论

- 三端脚本消息结构与当前《硬件层通讯规范.md》关键字段要求一致。
- 三端 Topic 命名符合现有分层约定（`hotel/device/status`、`hotel/device/data`、`hotel/device/command/result`、`hotel/security/event`）。
- 可作为“无实体硬件阶段”的最小联调验证基线。
