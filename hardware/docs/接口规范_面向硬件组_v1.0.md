# 智慧酒店物联网系统 - 硬件组接口规范 (v1.0)

> **版本**: v1.0.0  
> **更新日期**: 2026-04-16  
> **适用范围**: 硬件研发组、嵌入式软件组

---

## 1. 概述

本文档定义了智慧酒店系统中硬件设备（前台管理端、楼控、客房端）与后端软件系统之间的交互规范。旨在确保硬件功能与软件业务逻辑完美衔接。

### 1.1 通信架构
- **指令下发**: 后端 -> MQTT Broker -> 硬件 (Topic: `hotel/device/command`)
- **状态上报**: 硬件 -> MQTT Broker -> 后端 (Topic: `hotel/device/status`)
- **数据采集**: 硬件 -> MQTT Broker -> 后端 (Topic: `hotel/device/data/{type}`)
- **安防告警**: 硬件 -> MQTT Broker -> 后端 (Topic: `hotel/security/event`)
- **音视频流**: 硬件 <-> MQTT Broker <-> 后端 (Topic: `hotel/call/audio/{call_id}`)

---

## 2. MQTT 通信规范

### 2.1 主题结构
所有主题均遵循以下前缀: `hotel/`

| 业务分类 | 主题路径 | 方向 | 说明 |
| :--- | :--- | :--- | :--- |
| **设备注册/心跳** | `hotel/device/status` | 硬件 -> 后端 | 设备上线、下线及定时心跳 |
| **传感器数据** | `hotel/device/data/{type}` | 硬件 -> 后端 | 温湿度、光照、人体感应等 |
| **控制指令** | `hotel/device/command` | 后端 -> 硬件 | 下发控制命令（需签名验证） |
| **指令回执** | `hotel/device/command/result` | 硬件 -> 后端 | 指令执行结果反馈 |
| **安防事件** | `hotel/security/event` | 硬件 -> 后端 | SOS、火警、非法入侵等 |
| **VoIP 信令** | `hotel/call/signaling/{id}` | 双向 | 通话建立、挂断等信令 |
| **VoIP 音频** | `hotel/call/audio/{id}` | 双向 | 原始音频流 (PCM/G.711) |
| **AI 语音交互** | `hotel/ai/request/room/{id}` | 硬件 -> 后端 | 语音识别请求 |

### 2.2 消息格式 (JSON)
所有非流式数据必须采用 JSON 格式。

#### 2.2.1 设备上报 (Status/Data)
```json
{
  "device_id": "room_301_ctrl",
  "timestamp": "2026-04-16T10:00:00Z",
  "signature": "xxxx", 
  "data": {
    "status": "online",
    "battery": 100,
    "version": "v1.2.3"
  }
}
```

#### 2.2.2 指令下发 (Command)
```json
{
  "command_id": 12345,
  "device_id": "room_301_ctrl",
  "command_type": "light",
  "command_value": "on",
  "timestamp": "2026-04-16T10:00:01Z",
  "signature": "xxxx"
}
```

## 3. 业务功能衔接规范

### 3.1 客房控制 (Guest Room Control)
| 功能项 | 指令类型 (`command_type`) | 指令值 (`command_value`) | 硬件行为 |
| :--- | :--- | :--- | :--- |
| **灯光控制** | `light` | `on` / `off` | 继电器动作 |
| **空调控制** | `air` | `on` / `off` / `temp:26` | 红外/总线控制 |
| **窗帘控制** | `curtain` | `open` / `close` / `stop` | 电机控制 |
| **门锁控制** | `door` | `unlock` / `lock` | 电控锁动作 |
| **场景切换** | `scene` | `welcome` / `sleep` / `reading` | 组合动作 |

### 3.2 房卡管理 (RFID/NFC)
- **发卡 (Issue)**: 前台端调用 `issue_card` 指令。
- **刷卡开门 (Swipe)**: 
  1. 客房端读取 UID。
  2. 硬件上报 `hotel/security/event`，`event_type: "card_swiped"`。
  3. 后端校验权限，下发 `door: unlock` 指令。
  *注：为保证离线可用，硬件可缓存当前入住客人的卡 UID（由后端在 Check-in 时推送）。*

### 3.3 安防与交互 (Security & Interactive)
- **SOS 报警**: 硬件按下 SOS 键，立即上报 `hotel/security/event`，`event_level: "critical"`。
- **自动回锁**: 门锁开启后 8 秒未检测到关门，硬件应自动执行 `door_lock` 并上报状态。
- **AI 语音管家交互**:
  1. 硬件采集语音并通过 `hotel/ai/request/room/{id}` 发送（支持 Base64 音频或流式）。
  2. 后端处理后通过 `hotel/ai/response/room/{id}` 返回文字及语音 URL/Base64。
  3. 若 AI 指令包含设备控制（如“帮我开灯”），后端将另行下发 `command`。

## 4. 安全规范 (必读)

### 4.1 签名验证
为了防止指令重放及非法控制，所有下发指令均包含 `signature`。
- **算法**: HMAC-SHA256
- **密钥**: 设备注册审核通过后，由后端分配的 `device_key`。
- **待签名字符串**: `command_id + device_id + command_type + command_value + timestamp`

### 4.2 离线处理
- 硬件应具备本地离线逻辑（如本地物理开关、缓存卡 UID 开门）。
- 重新上线后，应补报离线期间产生的关键事件（带原始时间戳）。

## 5. 软件端待对接接口 (REST API)

| 接口地址 | 方法 | 说明 |
| :--- | :--- | :--- |
| `/api/v1/devices/register` | `POST` | 设备首次上线注册，获取 device_key |
| `/api/v1/ota/check` | `GET` | 检查固件更新，获取下载地址 |
| `/api/v1/environment/history` | `GET` | 硬件同步本地存储的环境数据至云端 |

### 5.1 OTA 更新流程
1. 硬件在心跳或启动时，向 `/api/v1/ota/check` 发送当前版本。
2. 后端对比数据库中最新的固件版本。
3. 若有更新，返回 `download_url` 及固件 `md5`。
4. 硬件下载固件，校验 MD5 后执行本地更新。

## 6. 异常代码定义

| 代码 | 说明 | 处理建议 |
| :--- | :--- | :--- |
| `ERR_SIG_INVALID` | 签名错误 | 检查 device_key 是否一致 |
| `ERR_CMD_TIMEOUT` | 执行超时 | 检查硬件执行器连接 |
| `ERR_NET_WEAK` | 网络信号弱 | 硬件触发自动重连逻辑 |
