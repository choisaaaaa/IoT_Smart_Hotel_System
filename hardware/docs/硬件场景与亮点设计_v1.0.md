# 智慧酒店硬件组 - 加分项与场景演进方案 (Phase 2)

> **文档定位**：
> 本文档为硬件组在核心基线（MVP）跑通后的**进阶演进路线图**。
> 所有列出的场景与新模块（如毫米波雷达），**必须在《硬件架构与设计基线_v1.0.md》中的基础功能 100% 稳定运行后，方可开展联调与代码合入**。如因赛期紧迫，本阶段功能允许延期或部分截断，不影响核心项目交付。

## 1. 软件定义的智能客房场景 (零硬件成本)

本章节场景无需额外增加硬件模块，纯粹依靠底层硬件（继电器、红外发射管）与后端业务逻辑（软件组）的联动来实现，是极高 ROI（投入产出比）的加分项。

### 1.1 “无感欢迎”模式
- **触发条件**：客房门外的 RC522 鉴权成功，且电磁门锁继电器（GPIO23）吸合开门的瞬间。
- **动作序列**：
  1. MQTT 发布门禁通过事件至后端。
  2. 后端下发场景联动指令。
  3. 硬件执行：闭合客房主灯继电器（GPIO17）、窗帘继电器（GPIO19）正转拉开窗帘；通过红外发射管（GPIO4）自动开启空调至 24℃（需预存红外码）。
- **商业价值**：提升初次入住的科技感体验。

### 1.2 “一键睡眠”模式
- **触发条件**：住客按下床头控制面板的“场景切换键”（如分配至预留的 GPIO4 按键），或通过手机 APP 触发。
- **动作序列**：
  1. 硬件切断客房内所有非必要照明（断开继电器 1）。
  2. 窗帘继电器反转闭合窗帘。
  3. 如果系统处于冬季模式，红外发射管发送空调辅热指令。
  4. 状态指示灯（GPIO14 WS2812B）全部熄灭，避免夜间光污染。

### 1.3 “按键式 AI 管家”联动
- **触发条件**：住客长按“呼叫前台键”（GPIO34）超过 3 秒（固件层识别为长按事件）。
- **动作序列**：
  1. 硬件亮起蓝色呼吸灯提示录音开始。
  2. 采集音频流并通过 MQTT 上送至后端。
  3. 后端对接大模型（GLM-4）进行意图识别（如识别出指令：“太热了，把温度调低点”）。
  4. 后端下发具体的设备控制指令。
  5. 硬件接收指令，通过红外模块调低空调温度。
- **商业价值**：完美闭环项目文档要求的“AI管家”需求，且彻底规避了“一直监听”带来的算力与隐私风险。

## 2. 硬件外设的进阶加分方案 (低成本高溢价)

本章节涉及在基础 BOM 单之外新增成本极低的硬件模块，以换取降维打击级别的业务亮点。

### 2.1 真·无感节能（毫米波雷达技术）
传统的红外热释电传感器（PIR）无法检测静止或睡眠中的人体，常导致误关灯。引入微动检测级别的毫米波雷达，可彻底解决酒店业“人走不断电”的痛点。

#### 硬件增项设计
- **新增模块**：`HLK-LD2410B` 或同类 24GHz 毫米波雷达模块（成本约 ¥15）。
- **引脚分配建议**：
  - 客房端 ESP32 的 `GPIO1` 和 `GPIO3` 已被烧录串口占用。
  - 可利用软串口（SoftwareSerial）或硬件 UART2，占用两个闲置的 GPIO（如原预留给红外接收但未强制要求的引脚）进行串口通信。
  - 若为简化代码，可直接配置雷达模块为“高低电平输出模式”，占用客房端 ESP32 的一个闲置输入 GPIO（如分配给预留的 `GPIO36` 或 `GPIO39`）。

#### 业务逻辑演进
- **进门即亮**：雷达检测到人体移动（输出高电平），硬件立即上报有人状态，联动开灯。
- **深度睡眠感知**：雷达检测人体呼吸微动，维持供电不断。
- **离房判定（极具商业价值）**：当雷达连续 3 分钟未检测到任何微动信号（输出持续低电平），判定住客已离开。硬件自动断开所有插座与照明继电器，切断空调红外信号，实现极致的被动节能。此项数据在答辩时具有极强说服力。

#### 人性化与客户体验补丁（Manual Override 权限移交）
- **痛点分析**：过度的“强制智能”极易引起反感。例如：住客下楼取外卖、去前台办事，或将宠物/重要需通电设备（如医疗仪器、充电电脑）留在房间时，若系统强制切断电源及空调，将导致极其糟糕的入住体验。
- **“客户为大”的兜底设计**：
  - **交互入口**：在客房物理面板或手机 APP/小程序 预留一个“保持常开（Keep-Alive）”或“手动模式”开关。
  - **固件层降级逻辑**：当该模式激活时，客房端 ESP32 的底层固件将强制屏蔽/忽略毫米波雷达传来的“无人（低电平）”中断信号。继电器（照明、插座）的状态彻底移交给住客的物理按键或 APP 指令控制。
  - **答辩价值（服务意识降维）**：在汇报该亮点时，强调**“真正的智能生态应当是提供高级的默认选项，但永远将最终决定权还给客户”**。这一“兜底退坡机制”能够极大拉升项目的服务温度与产品经理视角评分，展示团队不仅懂技术，更懂商业落地与客诉痛点。
