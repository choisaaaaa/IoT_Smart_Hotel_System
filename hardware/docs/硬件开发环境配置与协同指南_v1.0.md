# 智慧酒店硬件组 - 嵌入式开发环境配置与协同指南 v1.0

为规范本系统硬件开发环境，确保团队成员在代码协同与版本控制中的环境一致性，特制定本指南。

## 1. 核心架构与开发环境选型

鉴于本项目客房端存在高频多任务并发（基于 FreeRTOS 的网络与业务调度）、底层硬件加密（Mifare 扇区解密）及低延迟音频数据流处理（I2S/DMA）等系统级需求，**本项目硬件开发环境统一推荐采用【VSCode + ESP-IDF 官方插件】**。

### 1.1 ESP-IDF 的技术优势
- **系统资源调度**：提供底层 RTOS API 接口，可针对双核架构进行任务分配隔离，最大化系统并发性能。
- **原生协议与组件**：内置符合商用标准的 `wifi_provisioning` 组件及硬件密码学加速器接口。
- **工程化构建体系**：采用 CMake 构建与 Ninja 编译，支持模块化组件开发与依赖管理，符合现代嵌入式工程协同规范。

## 2. 团队开发与环境兼容策略

ESP-IDF 构建系统对操作系统环境变量、Python 依赖链条及构建工具栈的版本要求极为严格。为保障项目整体进度，避免单一节点的开发环境问题阻塞全局，本项目**支持在物理节点隔离的前提下，采用混合 IDE 模式进行协同开发**。

### 2.1 架构层解耦说明与统一组件库调用 (核心规范)
本项目的前台管理端、楼控端与客房端在物理链路上完全独立，各自运行闭环的固件程序，统一通过 MQTT 协议与后端服务器通信。
因业务层已通过标准的 JSON 协议包进行数据解耦，后端服务并不受制于前端硬件的具体编译框架。

**【强制调用规范】：**
无论开发人员分配至哪一个终端模块，均**禁止重复造轮子编写底层外设驱动**。
全组必须统一引用 `hardware/common_components` 下封装好的组件池（涵盖门禁读卡、环境采集、继电器控制、蜂鸣指示、MQTT联网等）。
具体接入及调用方法请移步详阅：👉 [《核心组件池 (Common Components) 使用教程》](../common_components/USAGE_TUTORIAL.md)。组件功能说明详见：[《核心组件池说明》](../common_components/README.md)。

### 2.2 开发环境应用约束
各研发成员可根据模块的系统开销指标及自身熟悉的工具链生态，在以下三种标准开发环境中择一使用。
**硬性约束**：所有编译框架生成的最终固件，必须严格遵守《统一 ESP32 引脚分配表 (Pinmap)》规范，并完全对齐《API及MQTT通信协议文档》中的报文标准。

## 3. 标准开发环境配置指南

### 3.1 方案 A：VSCode + ESP-IDF 官方插件（基线环境）
*适用模块：客房端高并发音频控制流、加密通信验证、以及对内存泄漏有严格管理要求的底层核心模块。*

**配置流程：**
1. **前置环境配置**：操作系统需预先安装 [Git](https://git-scm.com/) 与 [Python 3.8+](https://www.python.org/)，安装时**必须勾选“Add to PATH（添加至系统环境变量）”**。
2. **IDE 部署**：下载安装 [Visual Studio Code](https://code.visualstudio.com/)。
3. **插件安装**：在 VSCode 扩展市场检索 `Espressif IDF` 并完成安装。
4. **内核初始化**：
   - 运行 VSCode 命令面板（快捷键 `Ctrl+Shift+P` 或 `F1`），执行 `ESP-IDF: Configure ESP-IDF extension`。
   - 在弹出的配置向导中选择 `EXPRESS` 安装模式。
   - **路径规范**：指定 ESP-IDF 框架代码库及工具链的本地存储路径（**路径内容必须为全英文，严禁包含空格或特殊字符**）。
   - **下载优化**：建议在向导的下载源选项中切换为 `Espressif` 或 `Gitee` 镜像以提高组件获取成功率。
5. **工程构建与输出**：环境部署完成后，借助 VSCode 底部状态栏的专用工具条，依次执行 `Build`、`Flash` 及 `Monitor` 完成工程构建。

### 3.2 方案 B：VSCode + PlatformIO（工程化替代环境）
*适用模块：楼控端环境采集、前台端总线交互等常规业务节点。期望保持现代化的工程目录结构，同时需快速集成并复用大量开源组件库（如传感器驱动、第三方配网库）的开发场景。*

**配置流程：**
1. **IDE 部署**：下载安装 [Visual Studio Code](https://code.visualstudio.com/)。
2. **插件安装**：在 VSCode 扩展市场检索并安装 `PlatformIO IDE` 插件。
3. **内核初始化**：安装完毕后，VSCode 界面右下角将自动触发 PlatformIO Core 的后台初始化下载，请保持网络畅通，执行完毕后根据系统提示重启编辑器。
4. **工程创建与配置**：
   - 访问左侧 PlatformIO 菜单，进入 `PIO Home` -> `Open` -> `New Project`。
   - 输入规范的工程名称，开发板型号设定为 `Espressif ESP32 Dev Module`。
   - 框架（Framework）可根据底层需求选择 `ESP-IDF` 亦或 `Arduino`。
5. **依赖关系声明**：
   对于第三方库的管理，通过修改工程根目录的 `platformio.ini` 文件实现。配置保存后编译系统将自动完成依赖获取与版本锚定。配置示例如下：
   ```ini
   [env:esp32dev]
   platform = espressif32
   board = esp32dev
   framework = arduino
   monitor_speed = 115200 ; 规范全局串行通信波特率
   lib_deps =             ; 声明所需外挂组件包
       tzapu/WiFiManager @ ^2.0.16-rc.2
       knolleary/PubSubClient @ ^2.8
   ```
6. **代码编译**：编辑 `src/main.cpp`，使用状态栏工具条执行编译与烧录操作。

### 3.3 方案 C：Arduino IDE（快速原型验证环境）
*适用模块：硬件初期预研、单一外设驱动跑通测试及协议连通性的快速原型验证。*

**配置流程：**
1. **基础软件部署**：访问 Arduino 官方网站获取并安装 Arduino IDE 2.x 正式版。
2. **修改板级包索引**：
   - 导航至 `File` (文件) -> `Preferences` (首选项)。
   - 在“Additional boards manager URLs (附加开发板管理器网址)”字段内追加乐鑫官方支持库索引链接：
     `https://dl.espressif.com/dl/package_esp32_index.json`
3. **获取板级支持包 (BSP)**：
   - 导航至 `Tools` (工具) -> `Board` (开发板) -> `Boards Manager` (开发板管理器)。
   - 检索 `esp32`，定位由 `Espressif Systems` 发布的安装包并执行安装。
4. **设备交互配置**：
   - 编译前，于 `Tools` -> `Board` 列表中选定 `ESP32 Dev Module`。
   - 于 `Tools` -> `Port` 选择相应的串行通信接口。
   - 使用界面左上角的部署按钮执行代码验证与烧录，可通过“库管理器（Library Manager）”检索外部依赖。
