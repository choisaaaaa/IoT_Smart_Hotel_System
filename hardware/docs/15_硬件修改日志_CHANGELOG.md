## [2026-04-09] 三端业务收敛、容灾门控与 MQTT 联调完成

### 1. 三端业务逻辑与任务职责收敛
- `room_terminal`：命令分发、执行与回执流程拆分为独立函数；任务职责明确为 `sensor_task`（采集上报）与 `voice_task`（通话态音频）；`main` 保留初始化与守护。
- `floor_controller`：群控命令执行与回执发布独立封装；环境采样上报从主循环拆分为独立任务。
- `front_desk_terminal`：上线/心跳发布路径统一封装；心跳任务独立化，并预留按键事件任务骨架。

### 2. 网络容灾与离线降级最小实现
- 三端统一引入网络状态门控（`s_network_ready`）。
- 断网时自动进入离线降级：停止高频上报，保留本地逻辑执行与告警日志。
- 恢复连网后自动恢复上线与周期上报。

### 3. NVS 配置收敛（NVS 优先，默认值兜底）
- 三端主程序统一改为运行时读取配置：`Room_ID` / `Floor_ID` / `FrontDesk_ID` / `MQTT_BROKER_URI`。
- `service_network` Mock 层补齐上述键读取能力并完善字符串边界处理。
- MQTT 启动统一从运行时 Broker 变量读取，消除固定编译期硬编码地址。

### 4. MQTT 最小联调实测结果
- 三端脚本实测通过：上线消息、周期上报、指令接收与回执链路可用。
- `room_301` 已验证 `light_on`、`incoming_call`、`hangup_call`。
- `floor_03` 已验证 `light_on`、`light_off`。
- 回执主题 `hotel/device/command/result` 返回成功，具备后端联合联调条件。

## [2026-04-09] 三端业务流补齐（第二轮）

### 1. 客房端（Room Terminal）
- 命令执行链路扩展为“参数校验 -> 执行 -> 回执 -> 运行态上报”。
- 完整支持 `light_on/off`、`air_on/off`、`curtain_open/close`、`door_unlock/lock`、`incoming_call`、`hangup_call`。
- 主循环移除演示型模拟刷卡动作，仅保留守护逻辑，避免干扰真实联调。

### 2. 前台端（Front Desk）
- 完成按键业务流：`BTN_FRONT_CLEAR` 与 `BTN_FRONT_BROADCAST` 触发事件上报与下行控制。
- 新增前台下发房间命令能力（默认目标房间可由 `Room_ID` 配置读取）。
- 新增 `hotel/device/command/result` 订阅与回执日志处理。

### 3. 楼控端（Floor Controller）
- 扩展指令集：`broadcast_start`、`broadcast_stop`、`floor_reset`（占位执行路径）。
- 新增楼控运行态上报（走廊灯状态）与楼道报警按键事件上报。
- 新增本地策略入口函数，作为后续“光照阈值/时段联动”挂载点。
- 明确复位入口策略：楼控物理按钮仅用于报警，`floor_reset` 由前台电脑/后台远程命令触发。

## [2026-04-09] MQTT 最小稳定性补强与回归记录同步

### 1. service_mqtt 可用化
- 由占位实现升级为可运行实现，完成 `start / subscribe / publish` 主路径接入。
- 接入 MQTT 事件处理并支持订阅回调分发。

## [历史记录] 架构重构与组件库初始化

### 1. 架构与工程重构
- **分层架构确立**：确立并实施了 Driver → HAL → Service 的三层解耦架构。新外设驱动统一纳入 `common_components` 公共组件库。
- **通信规范对齐**：客房端、前台端、楼控端的 `main` 业务逻辑已与后端 MQTT/JSON 通信规范完成骨架对齐。
- **引脚分配策略**：统一在 `global_config.h` 中维护 ESP32-S3 冻结引脚表，彻底规避了 S3 的内部 Flash/PSRAM 冲突引脚及高风险启动引脚。所有终端的按键、继电器引脚已分配完毕并下沉至组件库配置中。

## 2. 组件库变更 (common_components)
- **新增驱动支持**：已完成 SG90、OLED(SSD1306)、RC522、电位器、LDR、NTC、DHT11、MQ-2、EC11、RD-03(OT2/UART)、红外发射/接收、RGB、有源蜂鸣器、继电器、W25Q64、INMP441、LMD2718、NS4168、PAM8403 的底层驱动封装。
- **组件移除与废弃**：
  - 矩阵键盘（4x4 Keypad）因原型调试复杂度过高，已从组件库及系统方案中移除。
  - 循迹模块（线巡/红外反射）因与智能酒店主线业务无关，明确不纳入系统方案。
- **音频链路方案**：确立 LMD2718（数字麦克风）+ NS4168（数字功放）为主线音频方案，PAM8403 降级为备选兼容方案。

## 3. 核心外设驱动修改明细
- **电位器 (Potentiometer)**：
  - 新增 `driver_potentiometer` 组件，实现模拟量输入（ADC）读取，提供百分比与原始值读取 API。
- **OLED 显示屏 (0.96" SSD1306)**：
  - `driver_oled` 组件由 Mock 模拟实现重构为基于 ESP-IDF `esp_lcd` 的真实 I2C 驱动。
  - 集成 5x7 ASCII 字模，引脚与分辨率宏统一定义于 `global_config.h`。
- **毫米波雷达 (RD-03 / S3KM1110)**：
  - 针对 RD-03 模块拆分为两个独立组件以适应不同接入需求：
    - `driver_rd03_simple`：基于 OT2 引脚的极简 GPIO 高低电平读取。
    - `driver_rd03_uart`：基于 UART 协议的被动收包与数据帧解析。
