# 三端功能增量方案（开发板丝印基准）v1.0

> **基准**：ESP32-S3-N16R8 双 USB-C 开发板，排针丝印与 `22_ESP32-S3-N16R8开发板排针接线表_三端杜邦线版.md` 一致。  
> **原则**：在现有能力上增量；**引脚以丝印可接为准**；禁用 `GPIO0/3/35/36/37/45/46` 外设负载；`GPIO19/20` 仅作低频输入慎用。  
> **侧重**：住客可感知体验 + 公区舒适度（不展开稳定性设计）。

---

## 0. 丝印可用 GPIO 速查（两排已引出、可作外设）

| 左排丝印 | 右排丝印 |
| :--- | :--- |
| `4,5,6,7,8,15,16,17,18` | `1,2,20,21,38,39,40,41,42,43(TX),44(RX),47,48` |
| `9,10,11,12,13` | （及 `3V3/GND/5V`） |

**注意**：部分开发板板载 RGB 占用 **`GPIO48`**。若与客房 **`IR_RX=48`** 冲突，需二选一：禁用板载灯或改 `IR_RX` 到其他空闲脚（如客房增量表里备用脚）。

## 1. 现状摘要（与增量关系）

| 端 | 已有能力（基线 + 杜邦线适配表） | 增量空间 |
| :--- | :--- | :--- |
| **客房** | 门禁、四路继电器、雷达、红外、音频、EC11、多键、OLED、W25Q64 预留 | 住客「安全/舒适/少打扰」类传感器 + 舵机演示机构 |
| **楼控** | MQ-2、光敏、**DHT11（替代 NTC）**、1 路继电器（代码里常见 CH1）、楼道键 | 第二路继电器、公区体验（香氛/新风机为演示可改继电器） |
| **前台** | RC522、WS2812、蜂鸣、双键 | 轻量输入（如「服务铃」外接键）或 NFC 二读卡器（需 SPI CS 另脚） |

## 2. 客房端（住客体验权重最高）

### 2.1 推荐新增功能（按住客感知排序）

| 优先级 | 功能 | 住客价值 | 建议外设 | 建议 GPIO |
| :---: | :--- | :--- | :--- | :--- |
| P1 | **门磁 / 行程开关** | 离房节能更准、「门未关好」可提示 | 磁簧模块（数字） | **`GPIO4`**（`22` 客房表未占用） |
| P2 | **水浸（卫生间/台盆下）** | 漏水早发现 | 水浸探头（数字） | **`GPIO9`**：仅当 **不焊接 W25Q64**（`CS` 未占用 SPI）时；否则与 P1 **二选一**或等打板释放脚 |
| P3 | **CO₂ 或 PM2.5** | 「闷」可量化，联动空调/新风（演示） | I2C 模块 | **共用 `GPIO21`（SDA）+ `GPIO8`（SCL）**；与 OLED 不同 I2C 地址 |
| P4 | **雨棚/百叶演示（舵机）** | 强展示「策略→执行」 | **SG90**（PWM） | **`GPIO4`**；与 P1 互斥时：舵机用 `GPIO4`，门磁改 **`GPIO9`**（且无 W25Q64） |
| P5 | **雨量（演示）** | 与舵机组成「下雨收棚」故事 | 雨量模块 DO | **`GPIO9`**（无 W25Q64）；或与门磁/舵机排优先级，**同一阶段只保留一个数字输入脚** |

**客房「数字输入 / PWM」脚冲突处理（默认可执行组合）**

| 默认可执行组合 | 接线要点 |
| :--- | :--- |
| **组合 A（优先住客体验）** | 门磁 `GPIO4` +（可选）I2C 空气传感器 `21/8` |
| **组合 B（优先答辩展示）** | 舵机信号 `GPIO4` + 雨量 DO `GPIO9`（前提：无 W25Q64） |
| **组合 C（全要时的顺序）** | 先定 **W25Q64 是否实装**；再定 `GPIO4` 给门磁还是舵机；`GPIO9` 给水浸或雨量二选一 |

### 2.2 客房增量接线（杜邦线）

- **门磁**：一端 `GPIO4`，一端 `GND`；另一触点常开/常闭按模块说明。  
- **SG90**：红线 `5V`，棕线 `GND`，橙线 `GPIO4`（PWM）；`5V` 轨就近 **1000µF** 对地。  
- **I2C 传感器**：`VCC 3.3V`，`GND`，`SDA→21`，`SCL→8`（确认与 OLED 地址不冲突）。

## 3. 楼控端（公区舒适度 + 住客「无感」安全）

### 3.1 推荐新增功能

| 优先级 | 功能 | 住客价值 | 建议外设 | 建议 GPIO |
| :---: | :--- | :--- | :--- | :--- |
| P1 | **第二路继电器** | 走廊辅灯 / 电梯厅灯分区，照度策略更细 | 第二路继电器 IN | **`GPIO16`**（`22` 表上楼控未用；注意与客房端区分——**每端独立一块板**） |
| P2 | **人体存在（PIR）** | 「人来灯亮」比纯光敏更可信 | HC-SR501 OUT | **`GPIO4`** |
| P3 | **雨感（公区）** | 关天窗/收外廊灯（演示） | 雨量数字 DO | **`GPIO9`** 或 **`GPIO10`**—楼控无 SPI 时可作 GPIO；若保留扩展 SPI 则改用 **`GPIO4`** 与 PIR 二选一 |

**楼控杜邦线版在 `22` 中已占**：`1/2/7/8/15/17/18`。  
**空闲丝印脚优先**：`4,5,6,9,10,11,12,13,16,20,21,38,39,40,41,42,43,44,47,48` 中剔除禁用脚后任选。

### 3.2 楼控增量接线示例

- **继电器 CH2**：IN → `GPIO16`，模块 `5V/GND`，与 CH1 共地。  
- **PIR**：`VCC 5V`（或 3.3V 视模块），`OUT→GPIO4`，`GND`。

## 4. 前台端（住客第一印象）

### 4.1 推荐新增功能

| 优先级 | 功能 | 住客价值 | 建议外设 | 建议 GPIO |
| :---: | :--- | :--- | :--- | :--- |
| P1 | **「取卡/还卡」检测** | 减少忘还卡、可触发欢迎语/灯效（演示） | 微动或光电槽 | **`GPIO4`** |
| P2 | **第二确认键（免扰确认）** | 前台一键确认已处理客房呼叫 | 轻触按键 | **`GPIO7`**（前台 `22` 表未占用） |

### 4.2 前台增量接线

- 微动：一脚 `GPIO4`，一脚 `GND`。  
- 按键：一脚 `GPIO7`，一脚 `GND`。

## 5. 与软件/文档的同步清单

1. **`global_config.h`**：凡新增 GPIO，增加宏（建议 `GLOBAL_*` 前缀一致）。  
2. **`hal_*` / `driver_*`**：新传感器先入 `common_components`，`main.c` 只调 HAL。  
3. **`22_...杜邦线版.md`**：若采纳本表增量脚，在对应端表格中追加一行，避免口头漂移。  
4. **`GPIO48` 冲突**：上电检查 `IR_RX` 与板载 RGB；冲突则改脚并更新宏。

---

## 6. 建议实施顺序（住客故事线）

1. **客房门磁 + 楼控 PIR**：「少打扰 + 公区更自然」  
2. **楼控第二路继电器**：「走廊策略更像真酒店」  
3. **客房舵机演示**：答辩「一眼看懂物联网闭环」  
4. **客房 I2C 空气质量**：「闷不闷」可量化  
5. **前台取卡检测**：「细节像真前台」
