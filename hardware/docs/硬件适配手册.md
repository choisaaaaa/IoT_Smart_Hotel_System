## 1. 系统架构总览

### 1.1 三端定位

| 设备 | 核心职责 | 主控建议 |
|------|---------|---------|
| 客房终端 | 火警、WebRTC通话、AI助手、硬件开关控制 | ESP32-S3 |


### 2.2 指令格式（Cloud → Hardware）

所有指令均为 JSON，发布到 `hotel/device/command/{type}/{device_id}`：

```json
{
  "command_id": 12345,
  "device_id": "ROO_01A2B3C4D5E6",
  "command_type": "light",
  "command_value": "on",
  "created_by": "web_admin",
  "timestamp": "2026-04-24T10:30:00.000000"
}
```

### 2.3 指令结果回传（Hardware → Cloud）

发布到 `hotel/device/command/result`：

```json
{
  "device_id": "ROO_01A2B3C4D5E6",
  "command_id": 12345,
  "command_type": "light",
  "status": "success",
  "result": "执行成功",
  "timestamp": "2026-04-24T10:30:00.000000"
}
```

### 2.4 消息签名机制

所有从硬件发出的 JSON 消息必须包含 `signature` 和 `timestamp` 字段：

```
签名算法: HMAC-SHA256
签名密钥: device_key（设备注册时后端下发）
签名原文: 将 payload 中除 signature 外的所有字段按 key 字典序排列后 JSON 序列化
```

伪代码：
```python
sign_str = json.dumps(sorted_payload, sort_keys=True, separators=(',', ':'), ensure_ascii=False)
signature = hmac_sha256(device_key, sign_str).hexdigest()
```

| 继电器 | GPIO | 控制对象 | 逻辑 |

### 3.4 指令处理映射

硬件固件需实现以下指令接收→GPIO操作的映射：

```
收到 command_type="light", command_value="on"   → GPIO17 输出 LOW (继电器1闭合)
收到 command_type="light", command_value="off"  → GPIO17 输出 HIGH(继电器1断开)
收到 command_type="air",   command_value="on"   → GPIO18 输出 LOW (继电器2闭合)
收到 command_type="air",   command_value="off"  → GPIO18 输出 HIGH(继电器2断开)
收到 command_type="curtain", command_value="open"  → GPIO5 输出 LOW
收到 command_type="curtain", command_value="close" → GPIO5 输出 HIGH
收到 command_type="door", command_value="unlock" → GPIO6 输出 LOW + 8秒定时器后自动 HIGH
收到 command_type="door", command_value="lock"   → GPIO6 输出 HIGH
```

### 3.8 插卡取电逻辑

```
1. RC522 检测到卡片 → 读取 UID
2. 发布 card_uid_detected 事件到 hotel/security/event
3. 后端验证卡片权限 → 返回 room_card_op 指令（action=sync）
4. 硬件收到 sync → 继电器4闭合（通电）+ 主灯开启
5. 卡片移除 → 10秒延时 → 继电器4断开（断电）
6. 上报占用状态到 hotel/devices/{device_id}/occupancy/report
```

占用状态上报格式：
```json
{
  "device_id": "ROO_...",
  "pir_activity": true,
  "card_power_state": 1,
  "power_consumption": 120.5,
  "timestamp": "..."
}
```

### 4.3 MQ-2 分压电路（关键安全项）

```
MQ-2 AO 输出 (0~5V)
        │
    ┌───┴───┐
    │ 1kΩ   │  ← R1
    ├───┬───┤
    │   │   │  ← 中点接 GPIO1 (ADC输入，最大3.3V)
    │ 2kΩ   │  ← R2
    ├───┴───┤
    │  GND  │
    └───────┘

分压比: Vout = Vin × R2/(R1+R2) = Vin × 2/3
当 Vin=5V 时, Vout=3.33V (安全)
```

> ⚠️ **警告**：MQ-2 的 AO 输出最高可达 5V，ESP32 GPIO 最大承受 3.3V。**必须使用分压电路**，否则会烧毁 GPIO！

| 上报间隔 | 30秒 | 传感器数据上报周期 |

### 4.6 指令处理映射

```
command_type="light:on"           → GPIO17 LOW  (继电器闭合，走廊灯亮)
command_type="light:off"          → GPIO17 HIGH (继电器断开，走廊灯灭)
command_type="broadcast_start"    → WS2812B 变蓝 + 蜂鸣器1声
command_type="broadcast_stop"     → WS2812B 恢复绿色

command_type="alarm_ack"          → WS2812B 变黄
command_type="alarm_reset"        → 停止蜂鸣器 + LED恢复绿色
```

### 4.7 火警触发与联动

```
1. MQ-2 ADC 值 > 阈值(80ppm) 或 GPIO18 按键按下
2. 发布 fire_alarm 到 hotel/security/event:
   {
     "device_id": "FLO_...",
     "event_type": "fire_alarm",
     "data": {"floor_id": "3", "type": "fire_alarm", "message": "第3层消防报警触发"},
     "level": "critical",
     "timestamp": "..."
   }
3. 本地响应：
   - WS2812B 全部变红
   - 蜂鸣器3声短鸣 → 5秒后持续鸣响
4. 等待 alarm_reset 指令复位
```

### 5.4 发卡流程（核心业务）

```
┌────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 前台放卡│───→│ RC522探测│───→│ 上报UID  │───→│ 后端确认 │
│ 物理动作│    │ 读取UID  │    │ 到云端   │    │ 卡片信息 │
└────────┘    └──────────┘    └──────────┘    └────┬─────┘
                                                   │
                     ┌─────────────────────────────┘
                     ▼
              ┌──────────────┐    ┌──────────┐    ┌──────────┐
              │ 后端下发     │───→│ RC522写入 │───→│ 蜂鸣器1声│
              │ room_card_op │    │ 卡片数据  │    │ LED绿色  │
              │ action=issue │    │          │    │ 灯墙更新 │
              └──────────────┘    └──────────┘    └──────────┘
```

详细步骤：

1. **物理放卡**：前台将空白房卡放到 RC522 感应区
2. **UID 探测**：RC522 通过 SPI 读取卡片 UID（4或7字节十六进制）
3. **上报事件**：发布 `card_uid_detected` 到 `hotel/security/event`
   ```json
   {
     "device_id": "FRO_...",
     "event_type": "card_uid_detected",
     "card_uid": "A1B2C3D4",
     "timestamp": "..."
   }
   ```
4. **后端响应**：后端通过 `room_card_op` 指令下发写卡数据
   ```json
   {
     "command_type": "room_card_op",
     "command_value": {
       "action": "issue",
       "card_uid": "A1B2C3D4",
       "card_type": "guest",
       "room_number": "301",
       "holder_name": "张三",
       "booking_id": "BK20260424001"
     }
   }
   ```
5. **写卡执行**：RC522 将房间号、卡类型等数据写入卡片扇区
6. **本地反馈**：蜂鸣器1声短鸣 + LED变绿 + 灯墙对应房间变绿
7. **上报结果**：发布 `card_issued` 事件到 `hotel/security/event`

### 5.5 退卡流程

```
1. 后端下发 room_card_op 指令，action="revoke"
2. RC522 擦除卡片数据（或标记为已退）
3. 蜂鸣器1声 + LED变橙
4. 灯墙对应房间变白（空置）
5. 发布 card_revoked 事件
```

### 5.6 刷卡开门联动

```
1. RC522 读取到已授权的卡片 UID
2. 发布 card_uid_detected 到 hotel/security/event（含 room_id）
3. 后端验证卡片权限
4. 验证通过 → 后端发送 door:unlock 指令到对应客房
5. 前台本地：蜂鸣器1声 + LED变绿
```

### 5.7 指令处理映射

```
command_type="issue_card"          → RC522 写卡 + 蜂鸣器1声 + LED绿
command_type="verify_card"         → RC522 读卡验证 + 蜂鸣器1/2声
command_type="swipe_card"          → 读取UID + 上报事件 + 请求开锁
command_type="room_card_op"        → 根据 action 执行发卡/退卡/同步
command_type="door:unlock"         → 蜂鸣器1声 + LED绿（远程开锁确认）
command_type="incoming_call"       → 蜂鸣器2声 + LED黄
command_type="hangup_call"         → 恢复正常
command_type="alarm_reset"         → 灯墙全白 + 停止蜂鸣器
command_type="buzzer"              → 蜂鸣器N声
```

## 6. WebRTC 通话适配

### 6.1 当前仿真器通话架构

仿真器使用 MQTT 传输 PCM 音频流，架构如下：

```
客房端                              前台/Web端
  │                                    │
  │── MQTT: hotel/call/signaling/{id} ──│  (信令：initiate/answer/hangup)
  │                                    │
  │── MQTT: hotel/call/audio/{id}/up ──│  (上行音频：16kHz PCM16)
  │                                    │
  │←─ MQTT: hotel/call/audio/{id}/down─│  (下行音频：16kHz PCM16)
```

### 6.2 真实硬件通话方案选择

| 方案 | 适用场景 | 延迟 | 复杂度 |
|------|---------|------|--------|
| **方案A：MQTT PCM 流**（当前） | ESP32 + I2S 麦克风/功放 | 200~500ms | 低 |
| **方案B：WebRTC P2P** | 需要低延迟的正式场景 | 50~150ms | 高 |
| **方案C：SIP/VoIP** | 与酒店PBX系统对接 | 100~200ms | 中 |

### 6.3 方案A：MQTT PCM 流适配（推荐起步方案）

#### 音频参数

| 参数 | 值 |
|------|-----|
| 采样率 | 16000 Hz |
| 位深 | 16-bit (PCM16) |
| 通道数 | 1 (单声道) |
| 每帧大小 | 2048 samples = 4096 bytes |
| 帧时长 | 128 ms |
| QoS | 0（音频流不重传） |

#### 通话信令流程

```
客房端                              前台/Web
  │                                    │
  │  1. PTT按键按下 (GPIO1)            │
  │── MQTT: signaling/{id} ──────────→│  action=initiate
  │     {caller_type:"room",           │  caller_id=room_id
  │      callee_type:"front_desk"}     │
  │                                    │
  │  ←─ MQTT: signaling/{id} ─────────│  action=answer
  │                                    │
  │  3. 订阅 audio/{id}/down           │
  │  4. 启动 I2S 采集 → MQTT 上行     │
  │── MQTT: audio/{id}/up ───────────→│  PCM16 二进制
  │←─ MQTT: audio/{id}/down ──────────│  PCM16 二进制
  │  5. I2S 功放播放下行音频           │
  │                                    │
  │  6. PTT再次按下 或 hangup 指令     │
  │── MQTT: signaling/{id} ──────────→│  action=hangup
  │  7. 停止 I2S + 取消订阅           │
```

#### 抖动缓冲（Jitter Buffer）

仿真器已实现抖动缓冲策略，硬件端建议同样实现：

```
1. 收到第一个下行音频包后，不立即播放
2. 等待队列中积累 2 个包（prebuffer）
3. 然后开始连续播放
4. 如果队列空了，重新进入 prebuffer 状态
5. 如果队列满了（>50包），丢弃最旧的包
```

## 7. RFID 发卡/开门适配

### 7.1 RC522 硬件接口

所有三端均使用 RC522 RFID 模块，通过 SPI 接口连接：

```
RC522 引脚    ESP32-S3 引脚    功能
─────────────────────────────────────
SDA/SS    →   GPIO10         片选（低有效）
SCK       →   GPIO12         SPI 时钟
MOSI      →   GPIO11         主出从入
MISO      →   GPIO13         主入从出
RST       →   可不接          复位（可选）
3.3V      →   3V3            供电
GND       →   GND            共地
```

### 7.2 RC522 Arduino 代码模板

```cpp
#include <MFRC522.h>

#define SS_PIN  10
#define RST_PIN -1  // 不接

MFRC522 rfid(SS_PIN, RST_PIN);

void init_rfid() {
  SPI.begin(12, 13, 11, 10);  // SCK, MISO, MOSI, SS
  rfid.PCD_Init();
}

String read_card_uid() {
  if (!rfid.PICC_IsNewCardPresent() || !rfid.PICC_ReadCardSerial()) {
    return "";
  }
  String uid = "";
  for (byte i = 0; i < rfid.uid.size; i++) {
    if (rfid.uid.uidByte[i] < 0x10) uid += "0";
    uid += String(rfid.uid.uidByte[i], HEX);
  }
  uid.toUpperCase();
  rfid.PICC_HaltA();
  return uid;  // 例如 "A1B2C3D4"
}

bool write_card_data(String room_id, String card_type) {
  MFRC522::MIFARE_Key key;
  for (byte i = 0; i < 6; i++) key.keyByte[i] = 0xFF;

  byte block = 1;
  MFRC522::StatusCode status = rfid.PCD_Authenticate(
    MFRC522::PICC_CMD_MF_AUTH_KEY_A, block, &key, &(rfid.uid));
  if (status != MFRC522::STATUS_OK) return false;

  byte buffer[16] = {0};
  room_id.getBytes(buffer, min((int)room_id.length()+1, 12));
  buffer[12] = card_type.charAt(0);  // 'g'=guest, 'm'=master

  status = (MFRC522::StatusCode)rfid.MIFARE_Write(block, buffer, 16);
  return (status == MFRC522::STATUS_OK);
}
```

```
时序图：

前台硬件          MQTT Broker         后端API           客房硬件
  │                  │                  │                  │
  │ 1.放卡到RC522    │                  │                  │
  │ 2.读取UID        │                  │                  │
  │──card_uid_detected──→│              │                  │
```

### 7.4 刷卡开门（客房端）


```cpp
  const char* cmd_type = doc["command_type"];
  const char* cmd_value = doc["command_value"] | "";
  int cmd_id = doc["command_id"] | 0;

  bool success = false;
  String result_msg = "";

  if (strcmp(cmd_type, "light") == 0) {
    if (strcmp(cmd_value, "on") == 0) {
      digitalWrite(GPIO_RELAY_LIGHT, LOW);  // 继电器低电平触发
      success = true;
      result_msg = "灯光已开启";
    } else if (strcmp(cmd_value, "off") == 0) {
      digitalWrite(GPIO_RELAY_LIGHT, HIGH);
      success = true;
      result_msg = "灯光已关闭";
    }
  }
  else if (strcmp(cmd_type, "door") == 0) {
    if (strcmp(cmd_value, "unlock") == 0) {
      digitalWrite(GPIO_RELAY_DOOR, LOW);
      start_relock_timer(8000);  // 8秒后自动回锁
      success = true;
      result_msg = "门锁已开启";
    }
  }
  else if (strcmp(cmd_type, "scene") == 0) {
    if (strcmp(cmd_value, "welcome") == 0) {
      apply_scene_welcome();
      success = true;
      result_msg = "迎宾模式已激活";
    }
  }
  else if (strcmp(cmd_type, "room_card_op") == 0) {
    success = handle_room_card_op(doc["command_value"]);
    result_msg = success ? "房卡操作成功" : "房卡操作失败";
  }
  else if (strcmp(cmd_type, "alarm_reset") == 0) {
    reset_alarm();
    success = true;
    result_msg = "报警已复位";
  }

  publish_command_result(cmd_id, cmd_type, success, result_msg);
}
```

### 10.4 签名生成模板（C++）

```cpp
#include <mbedtls/md.h>

String generate_signature(JsonDocument& payload, const char* device_key) {
  // 1. 移除 signature 字段
  payload.remove("signature");

  // 2. 添加 timestamp（如果不存在）
  if (!payload.containsKey("timestamp")) {
    payload["timestamp"] = get_iso_timestamp();
  }

  // 3. 按 key 排序并序列化
  String sorted_json = sort_and_serialize(payload);

  // 4. HMAC-SHA256
  byte hmac_result[32];
  mbedtls_md_context_t ctx;
  mbedtls_md_init(&ctx);
  mbedtls_md_setup(&ctx, mbedtls_md_info_from_type(MBEDTLS_MD_SHA256), 1);
  mbedtls_md_hmac_starts(&ctx,
    (const unsigned char*)device_key, strlen(device_key));
  mbedtls_md_hmac_update(&ctx,
    (const unsigned char*)sorted_json.c_str(), sorted_json.length());
  mbedtls_md_hmac_finish(&ctx, hmac_result);
  mbedtls_md_free(&ctx);

  // 5. 转为十六进制字符串
  String signature = "";
  for (int i = 0; i < 32; i++) {
    char hex[3];
    sprintf(hex, "%02x", hmac_result[i]);
    signature += hex;
  }
  return signature;
}
```

```cpp
  const char* action = cmd_value["action"] | "";

    }

    // 验证 UID 匹配
    String current_uid = read_card_uid();
    if (current_uid != String(card_uid)) {
      // UID 不匹配，强制同步（仿真器行为）
    }

    // 写入卡片数据到 Block 1
    return write_card_data(String(room_number), String(card_type));
  }
  else if (strcmp(action, "revoke") == 0 || strcmp(action, "deactivate") == 0) {
```
