# 房卡数据契约（前台固件 ↔ 后端 ↔ Web）

本文档归纳 **MIFARE 扇区 1 应用块** 与 **MQTT `room_card_op` / `card_issued`** 字段，与 `iot-hotel-backend`、`iot-hotel-web` 当前实现一致；前台 ESP32 工程已按此实现写卡与上报。

## 1. 扇区载荷（AES-128-ECB，单块 16 字节）

| 业务 | 明文（UTF-8，PKCS#7 填充后加密） | 约束 |
|------|----------------------------------|------|
| 客房卡 `guest` | `ROOM:<房号>` | 房号 ≤10 字符（与 `card_mifare_encrypt_room_payload` 一致） |
| 特权卡 `master` / `floor` / `staff` / `emergency` 等 | `TYPE:<card_type>` | `strlen("TYPE")+1+strlen(card_type) ≤ 15` |

密钥：NVS `HotelCard_AES128Hex`（32 hex），否则 `GLOBAL_CARD_AES128_HEX_DEFAULT`；**前台、客房、后端登记须一致**。

MIFARE 工厂默认 Key A `FF..FF` 写扇区 1 块 0（与现有 `k_default_card_key` 一致）。

## 2. `room_card_op` 的 `command_value`（JSON）

| 来源 | `action` | 主要字段 | 固件行为 |
|------|----------|----------|----------|
| `POST /devices/room-card` | `issue` / `revoke` | `booking_id`(number), `room_number`, `card_uid`(占位 PRIV_*) | `issue`：写 `ROOM:<room_number>`，读 UID，发 `card_issued`（含 `booking_id` 字符串）；`revoke`：擦除扇区块 |
| `rfid/issue-privilege` MQTT | `issue` | `card_type`, `holder_name`, `expiry_date`… | 写 `TYPE:<card_type>`，发 `card_issued` |
| `mqtt.service` 感应已知卡 | `sync` | `card_uid`, `card_type`, `holder_name`, `room_number` | 按类型写 `ROOM:` 或 `TYPE:` |
| 未知卡 | `sync_clear` | `card_uid` | 擦除扇区块 |
| 作废卡 | `deactivate` | `card_uid` | 擦除扇区块 |

**注意**：后端下发的 `booking_id` 常为 **JSON number**，固件须按数字或字符串双兼容解析，否则 `card_issued` 缺少 `booking_id`，`rfid_cards` 中 `PRIV_*` 占位无法替换为真实 UID。

## 3. `card_issued` 安防事件（`hotel/security/event`）

嵌套 `data` 对象（后端 `handleSecurityEvent`）：

| 字段 | 必填 | 说明 |
|------|------|------|
| `card_uid` | 是 | 十六进制 UID 字符串 |
| `room_id` | 客房卡建议 | **房号字符串**（如 `301`），与 DB `room_number` 匹配更新 |
| `booking_id` | 客房卡建议 | 字符串或后端可转数字，用于 `WHERE booking_id = ? AND card_uid LIKE 'PRIV_%'` |
| `card_type` | 可选 | `guest` / `master` / … |
| `action` | 固定 | 固件填 `issue` |

特权卡签发依赖 `pending_privilege_issue:<device_id>` 缓存时，**仅 `card_uid` + 设备号**即可闭环写库。
