## 2. 已完成能力（已闭环）

### 2.1 代码与工程

- 三端工程可独立构建通过：`room_terminal`、`front_desk_terminal`、`floor_controller`。
- `cJSON` 依赖已统一为 ESP-IDF Component Manager 方式。
- 三端 `main.c` 完成业务收敛，形成“初始化 + 任务 + 守护”结构。

### 2.2 网络与配置

- 已实现网络状态门控（断网降级、恢复后继续上报）。
- 已实现 NVS 优先配置读取，默认值兜底（设备 ID / MQTT Broker URI）。
- 已具备基础离线场景下的行为可控能力（停止高频上报，保留关键路径）。

### 2.3 协议与联调

- MQTT 基础链路验证通过：上线、心跳/遥测、下行命令、执行回执。
- 客房端已验证命令：`light_on`、`incoming_call`、`hangup_call`。
- 楼控端已验证命令：`light_on`、`light_off`。
- 回执主题 `hotel/device/command/result` 可稳定返回，具备后端联合联调条件。

### 2.4 文档与交付

- 已形成制图输入文档：`03_硬件制图与实施交付手册_原型验证分板版_v1.0.md`。
- 已形成协议基线文档：`02_硬件层通讯规范.md`（v1.2.0）。
- 已形成变更可追溯文档：`15_硬件修改日志_CHANGELOG.md`。
- 已形成测试可追溯文档：`MQTT联调测试报告_2026-04-09.md`。
- 已形成联调签收文档：`17_硬件联调验收清单.md`。

## 3. 未完成项与风险边界

## 3.1 未完成项（当前阶段允许）

- `service_mqtt` 指数退避重连策略尚未落地。
- 24h 长时压测与统计报告尚未输出。
- TLS（`mqtts://`）证书链路未实装。
- 外设在环（HIL）全链路测试待外设齐套后执行。

## 3.2 风险边界说明

- 当前验证以脚本联调为主，不能替代真实硬件负载和电气噪声环境测试。
- 量产前仍需完成“重连鲁棒性 + 安全加密 + 长稳测试”三项门槛。

---

## 4. 下一阶段建议（按优先级）

1. **P0：实装 MQTT 退避重连**（1s/2s/4s/8s…上限 60s）。  
2. **P0：执行 24h 联调压测**（统计丢包率、回执成功率、重连次数、时延）。  
3. **P1：TLS 预埋与切换位**（保留 `mqtt://` 与 `mqtts://` 双配置）。  
4. **P1：外设在环 HIL 用例**（门禁、继电器、音频、传感器逐项实测）。
