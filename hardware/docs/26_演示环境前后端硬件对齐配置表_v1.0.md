# 演示环境：硬件 ↔ 后端 / 硬件 ↔ Web 对齐配置表（v1.0）

本文档供 **照表改 NVS、库、环境变量**，与仓库内前后端及三端固件行为一致。  
主题前缀定义见 `hardware/common_components/config/config_global/include/global_config.h`。

---

## 表一：固件 ↔ 后端 / MQTT / 数据库

**用途**：换板、换店、本地联调时，保证注册、订阅、下发指令、验签、安防事件能通。

| 配置项 | 前台 `front_desk_terminal` | 客房 `room_terminal` | 楼控 `floor_controller` | 说明与改法 |
|--------|---------------------------|----------------------|-------------------------|------------|
| **注册 HTTP** | `service_auth_resolve_register_url`：优先 NVS `HTTP_API_BASE`，否则由 `MQTT_BROKER_URI` 推导同机 `:9000`，失败则用代码内默认公网 | 同左 | 同左 | 本地演示：NVS 写 `HTTP_API_BASE=http://<PC IP>:9000`（无尾缀 `/api/v1` 按你们 `service_auth` 实现为准） |
| **注册路径** | 解析结果一般为 `{API}/api/v1/devices/register` | 同左 | 同左 | 后端路由见 `backend/iot-hotel-backend` 设备注册接口 |
| **hotel_id（注册）** | 代码写死 `3`（`main.c` 内 `service_auth_perform_registration_blocking`） | 写死 `3` | 写死 `3` | **必须与** `devices.hotel_id`、登录门店一致；换店需改三端源码或后续改为 NVS |
| **device_id 组成** | `front_desk_` + NVS `FrontDesk_ID`（缺省见 `FRONT_DESK_ID_DEFAULT`） | `room_` + NVS `Room_ID`（房号字符串，如 `301`） | `floor_` + NVS `Floor_ID`（如 `03`） | DB `devices.device_id` **必须同字符串**；改 NVS 后需重新注册或手工改库 |
| **device_type（注册）** | `"front_desk"` | `"room"` | `"floor"` | 决定 MQTT 指令主题段与后端 `sendDeviceCommand` 拼 topic |
| **MQTT Client** | `service_mqtt_start(uri, device_id)`，一般为 **与 device_id 同名字符串** | 同左 | 同左 | 与 EMQX 客户端 ID 策略一致即可 |
| **指令订阅 topic** | `hotel/device/command/front_desk/{device_id}` | `hotel/device/command/room/{device_id}` | `hotel/device/command/floor/{device_id}` **及** `hotel/device/command/room/{room_device_id}` | 后端发布：`hotel/device/command/{device_type}/{device_id}`（见 `mqtt.service.ts` `sendDeviceCommand`） |
| **指令回执 topic** | `hotel/device/command/result`（全局） | 同左 | 同左 | 固件发布带 `device_id`、`command_id`、`signature` |
| **状态/心跳 topic** | `hotel/device/status/front_desk/{device_id}` | `hotel/device/status/room/{device_id}` | `hotel/device/status/floor/{device_id}` | 与 `publish_device_online_status` 等实现一致 |
| **传感器数据 topic** | `hotel/device/data/{sensor_type}/{device_id}`（本机上报） | 同左 | 楼控本体：`.../{sensor_type}/floor_xx`；若缝合双发则还有 `.../room_yy` | 后端 `hotel/device/data/` 消费逻辑见 `mqtt.service.ts` |
| **安防事件 topic** | `hotel/security/event` | 同左 | 同左 | 需带 `timestamp`、`signature`；已审核设备后端验签 |
| **音频上下行** | `hotel/device/audio/uplink/...`、`audio/downlink/...`（见 `voice_session`） | 同左 | 楼控通常不用 | Agent 演示时对齐 Broker ACL |
| **NVS：Broker** | `MQTT_BROKER_URI` | 同左 | 同左 | 覆盖 `global_config.h` 默认；须与后端 `MQTT_HOST`/`MQTT_PORT` 可达同一 Broker |
| **NVS：HTTP** | `HTTP_API_BASE`（可选） | 同左 | 同左 | 见上 |
| **NVS：业务** | `FrontDesk_ID`、`Room_ID`（代客目标房）、`Floor_Sensor_Device_Id`（抄楼控，如 `floor_03`） | `Room_ID`、`Floor_Sensor_Device_Id`（订阅楼控烟感等） | `Floor_ID`、`Room_ID`（缝合板双发/代客房 topic 时用） | **前台 OLED 楼控数据**：`Floor_Sensor_Device_Id` = 楼控 `device_id` |
| **数据库 `devices`** | 存在 `device_id=front_desk_xx`，`audit_status=approved`，`hotel_id` 与注册一致，`device_key` 与板子 NVS 注册结果一致 | 存在 `device_id=room_301` 等 | 存在 `floor_03`；若楼控双发客房数据，还需 `room_xxx` 行且 **演示环境密钥可与楼控同源** | `scripts/seed-demo-data.js` 仅示例；真机以注册为准 |
| **后端 `.env`** | `VOICE_AGENT_EXTRA_APPROVED_DEVICE_IDS` 可填兜底 `device_id`（未审核 Agent 时） | 一般不需要 | — | 见 `backend/iot-hotel-backend/.env.example` |

**MQTT 主题常量速查（代码）**

| 宏 | 值 |
|----|-----|
| `GLOBAL_TOPIC_DEVICE_COMMAND_PREFIX` | `hotel/device/command` |
| `GLOBAL_TOPIC_DEVICE_STATUS_PREFIX` | `hotel/device/status` |
| `GLOBAL_TOPIC_DEVICE_DATA_PREFIX` | `hotel/device/data` |
| `GLOBAL_TOPIC_DEVICE_COMMAND_RESULT` | `hotel/device/command/result` |
| `GLOBAL_TOPIC_SECURITY_EVENT` | `hotel/security/event` |

## 表二：演示场景 ↔ Web 前端 / 登录与数据

**用途**：演示账号、酒店、设备列表、报警弹窗与固件侧 `device_id`/事件类型一致，避免「板子在线但页面选错店、收不到 WS」。

| 配置项 | 建议取值 / 检查 | 代码或页面依据 | 改法 |
|--------|-----------------|----------------|------|
| **浏览器访问** | 与后端 `ALLOWED_ORIGINS` 一致，如 `http://localhost:5173` | `backend/iot-hotel-backend/.env` | CORS 不匹配会导致登录或 WS 失败 |
| **登录用户 `hotel_id`** | 与固件注册 `hotel_id=3` 及 `devices.hotel_id` 一致 | JWT payload / `users` 或 `staff` 与酒店绑定 | 换店：改库或换账号，并同步改固件 `hotel_id` |
| **设备列表中的前台** | `device_type = front_desk`，`device_id = front_desk_xx` | 管理端设备管理相关页 | 与 NVS `FrontDesk_ID` 一致 |
| **设备列表中的客房** | `device_type = room`（或界面文案「智能终端」），`device_id = room_301` | 同上 | 与 NVS `Room_ID` 一致；**前台缝合板仅演客房时**若仍用 `front_desk` 工程，云端仍显示为前台，需接受或改固件角色（见下） |
| **IoT 控制 / 场景下发** | 所选 `device_id` 必须与 MQTT 订阅 topic 完全一致 | `mqtt.service.ts` `sendDeviceCommand` | 下发出错优先查 DB `device_id` 与固件日志订阅 topic |
| **WebSocket 连接** | 同一后端 Socket.IO  origin | `frontend/iot-hotel-web` 中 `initWebSocket` / API base | 与 `APP_PUBLIC_URL`、反向代理一致 |
| **安防弹窗 `security_event`** | 需订阅酒店维度房间，如 `front_desk_hotel_{hotel_id}` | `mqtt.service.ts` `handleSecurityEvent` 末尾 `io.emit(..., hotelRoom)`；`App.vue` / `utils/websocket.ts` 监听 | 登录酒店与 `hotel_id` 不一致会收不到弹窗 |
| **报警事件类型** | `fire_alarm`、`sos_alarm`、`floor_fire_suspected`、`room_sos_pressed` 等 | `App.vue`、`websocket.ts`、`AlarmAlertModal.vue` | 与固件 `event_type` 一致 |
| **消防报警列表 API** | 需带鉴权，`hotel_id` 过滤 | `environment.controller.ts` `getFireAlarms` 等 | `device_alarms` 表需有数据（MQTT 安防事件写入） |
| **代客开锁（前台刷卡）** | 前台 `publish_room_command` 发往 `room_{房号}` | `front_desk_terminal/main.c` | 库中须存在对应 `room_xxx` 且在线或可演示 |

**说明（前台缝合 ↔ 真客房演示）**

- 当前 **`front_desk_terminal` 注册类型固定为 `front_desk`**，Web「客房设备」列表若只展示 `device_type=room`，则 **不会把同一块板列成客房**，除非：
  - 演示时仍用 **前台入口** 控灯/锁，或  
  - 后续在固件增加 **NVS 角色**（注册为 `room` + 订阅 `command/room/...`），再冻结一版二进制。  
- 本表不替代 **杜邦线与 GPIO**，接线仍以 `24_硬件杜邦线傻瓜接线教程`、`front_desk_terminal/CMakeLists.txt`、`room_terminal/CMakeLists.txt`、`floor_controller/CMakeLists.txt` 为准。
